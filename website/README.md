# WeekPact website

An Astro static site alongside the Flutter app. Astro generates crawlable HTML and adds JavaScript only for invitation handoff. No application server or Supabase credentials are needed.

## Run locally

Requires Node 22.12 or newer.

```sh
cd website
npm ci
cp .env.example .env
npm run dev
npm test
npm run build
npm run preview
```

The output is `website/dist/`. Flutter's `web/` directory remains its own application target.

## Configuration

Set these in `website/.env` or the hosting provider's build environment, then rebuild:

- `SITE_URL`: HTTPS origin, defaults to `https://weekpact.codepeaktrail.dev`. Sets canonical URLs and the sitemap.
- `PUBLIC_IOS_INSTALL_URL`: optional App Store or public TestFlight URL.
- `PUBLIC_ANDROID_INSTALL_URL`: optional Google Play URL.
- `IOS_APP_ID`: Apple application identifier, defaults to the current project's `R5L8RZTV6R.dev.codepeaktrail.weekpact`. Confirm it matches the signed app's application-identifier entitlement.
- `ANDROID_PACKAGE_NAME`: defaults to the current `com.example.keepup`; change alongside the app before publishing.
- `ANDROID_SHA256_CERT_FINGERPRINTS`: comma-separated SHA-256 signing certificate fingerprints. Use the Play App Signing certificate for Play builds. Empty means Android association is disabled (`assetlinks.json` contains an empty array).

Download links are omitted until supplied. These are public build settings; do not add credentials.

## Pages and invitation behavior

- `/`: indexable product homepage.
- `/invite/?invite=TOKEN`: invitation handoff to `weekpact://invite?invite=TOKEN` when the visitor taps **Open WeekPact**.
- `/invite/`: instructions for finding invitations in the app inbox.
- `/open/`: generic app opener. Invite query parameters on `/` or `/open/` forward to `/invite/`.

Tokens must be exactly 64 lowercase hexadecimal characters, as generated by the invitation function. This checks format only; authentication, validity, expiry, crew preview, acceptance and decline remain in the mobile app. Opening the webpage never accepts an invite. Unrecognized redirect destinations are ignored. The page does not fetch crew data or send tokens to analytics. Without JavaScript, users can open the app manually and use Crews → Invites.

Invite/open pages use `noindex`, are excluded from the sitemap, and have a no-referrer policy. Configure hosting access logs to redact invite query strings if logs are retained.

## Publish

Use a static host with project root `website`, build command `npm run build`, and publish directory `dist`. Point `weekpact.codepeaktrail.dev` to that host and enable HTTPS. Upload the whole output, including `.well-known/`. No SPA catch-all rewrite is needed.

`public/_headers` supplies headers for hosts supporting that format (such as Cloudflare Pages and Netlify). On another host, configure equivalent headers, especially `Content-Type: application/json` for the extensionless Apple association file. Both association endpoints must return their JSON directly over HTTPS without redirects:

- `/.well-known/apple-app-site-association`
- `/.well-known/assetlinks.json`

The website prepares association files; native Universal/App Links still need configuration and a new app build:

1. iOS: add Associated Domains capability with `applinks:weekpact.codepeaktrail.dev` to the Runner target and signing profile.
2. Android: set the production package name and add an auto-verified HTTPS VIEW intent filter with DEFAULT/BROWSABLE categories for this host, limited to `/invite` and `/open`. Supply the signing fingerprint above.
3. Rebuild/install and test a real email invitation on a physical device, both with and without the app installed. The website's button uses the already registered `weekpact` scheme as a fallback.

Only after the site is hosted and verified, set the invitation Edge Function secret:

```sh
supabase secrets set APP_BASE_URL=https://weekpact.codepeaktrail.dev/invite/
```

This changes future crew invitation emails. Existing emailed links do not change. Keep Flutter's `INVITE_REDIRECT_BASE` and the Supabase Auth redirect allow-list on their working custom scheme: this site is not an authentication callback handler. Crew email links and authentication callbacks have separate jobs.

No live email settings, native entitlements, DNS, or hosting were changed when creating this website.
